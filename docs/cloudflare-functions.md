## 日記ジョブの保存条件

ブロック更新とジョブ・outboxの記録はSQLiteトリガーにより同じD1処理で確定する。Queue送信後の中断や重複配送に備え、回復用Cronが永続記録を確認する。1日1ジョブ、5秒の静穏待ちと最大30秒の集約、180秒のlease、最大3試行を実装した。UTC日ごとの所有者全体の上限は20試行とし、元の所有者・対象日ごとの上限より厳しくした。1試行で複数のAIリクエストが発生するため、これはAI呼び出し回数20回の保証ではない。

保存直前に世代、lease、設定の版、日記編集の版、停止設定を同じD1トランザクションで確認する。古い結果を保存しない。生成中に人が日記本文を編集した場合はその依頼を停止し、再試行で人の編集を上書きしない。新しいブロック更新または明示的な再生成依頼で後続の依頼を作れる。直近5版の本文・要約・得点を履歴に保管し、期待した更新時刻が一致するときだけ復元する。

導入時は停止状態で、過去のジョブを一斉作成しなかった。初期の隔離試験では架空の日付1日だけを一時許可し、試験後に設定を戻した。その後、利用者の依頼で2026-10-29 22:27 JSTから、新しく追加する出来事だけの自動生成を有効にした。有効化時点の既存entry・既存ブロックの生活日は保護し、追加・編集・削除や明示的な依頼でも過去日記を再生成しない。DBへの追加時に登録した新規ブロックだけを入力へ含める。架空の新規記録で実Queue・モデル・保存・画面更新を確認し、試験用記録は片付けた。コピーした既存の日記は再生成していない。

## 旧実装からの修正

- 日記整形で、見出し直後の空行を空セクションと誤認する正規表現を修正。まとめセクションの除去も本文の途中で止まらないようにした。
- 非公開R2画像をOpenAIへdata URL、Google・Anthropicへ画像データとして渡す。Google OCRへ文字列のURLだけを送る経路は置き換えた。 画像とJSON全体を重ねてメモリに展開せず、R2からストリームで送る。5枚計45MiBの模擬画像で送信処理を検証した。この容量試験と、実モデルでの架空文字画像の認識試験は区別する。
- Lovable AI Gatewayへの既定経路を削除。指定モデル・キーがない機能は未設定として止める。別モデルへの自動切り替えは行わない。
- Anthropicのキー接続試験を固定の古いモデルの生成からモデル一覧のGETへ変更。モデル単位の試験では、その指定モデルを参照できるかを別に確認する。[提供元のモデル参照API](https://platform.claude.com/docs/en/api/models/list)
- 未来の予定をRESTで追加するとき、作成日時まで未来にしてDB制約へ抵触する経路を修正。予定の開始・終了時刻と現在の作成日時を分ける。既存レコードは変更しない。
- トップページの公開経路と元のログイン画面デザインを復元。新規登録・匿名ログインは決定済みの方針に従って無効。採点にもモデル選択欄を追加した。

## 出来事の時刻と並び順

文章だけの出来事は入力欄から直接保存できる。分類・タグや画像を含む記録は確認画面も使える。新規の出来事・メモに明確な時刻表現や食事・時間帯の手がかりがあれば、Worker内のルールで発生時刻の候補を作る。推定に外部モデルへのリクエストは追加しない。別の日に移す必要がある表現、複数の時刻、予定など判断がつかないものは時刻未確認にする。

`event_timing` は発生時刻の情報と由来、`timeline_placement` は本人がドラッグで指定した前後関係を持つ。時刻候補やドラッグで `occurred_at` を書き換えない。時刻表示から時間帯・正確な時刻・不明を選べる。本人の時刻指定と本文はブラウザー経由で確定し、機械APIからの変更はD1で拒否する。既存行への時刻推定の一括適用は行わない。

マイグレーション `0008_block_timing.sql` を適用してからWorkerと画面を配備する。ローカルでの確認は `npm run test:worker -- --production`。本番用の画面をビルドして `--ui` を追加すると、架空データによる画面テストも実行する。
